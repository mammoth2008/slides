AFTER UPDATE 触发器已经执行，是否表示包含该 UPDATE 的事务已经 COMMIT？

正确答案：否，AFTER 只表示在该语句事件之后，事务仍可能回滚

触发时机属于语句执行过程，不能把 AFTER 误解为整个事务已经持久提交

将 DML 事件与行级触发器中可用的行值匹配

正确答案：INSERT → 使用 NEW 读取新插入的行；UPDATE → 使用 OLD 和 NEW 比较修改前后的行；DELETE → 使用 OLD 读取被删除的行

不存在的前态或后态不能被引用，具体语法名称仍要按 DBMS 核查

哪些规则通常应优先使用声明式约束而不是触发器？

正确答案：主码唯一且非空、外码必须引用已有目标、成绩必须位于允许范围

PRIMARY KEY、FOREIGN KEY 和 CHECK 能直接、可见地表达这些完整性规则；自动日志或复杂动作才更可能需要触发器或明确应用流程

第 6 题 / 共 7 题 · 排序题

设计触发器时按风险控制顺序排列

  1. 分析动作失败、同类触发器顺序和可能的触发链
  2. 用多行变更、回滚和边界值测试最终状态
  3. 先判断声明式约束或显式应用流程是否已经足够
  4. 明确事件、时机、粒度、条件和 OLD／NEW 引用

正确答案：先判断声明式约束或显式应用流程是否已经足够 → 明确事件、时机、粒度、条件和 OLD／NEW 引用 → 分析动作失败、同类触发器顺序和可能的触发链 → 用多行变更、回滚和边界值测试最终状态

触发器是隐式执行对象，设计时必须先证明必要性，再控制执行和失败传播

第 7 题 / 共 7 题 · 回想题

触发器 A 写入审计表，审计表上的触发器 B 又更新原业务表。为什么这类触发链危险？应怎样治理？

对照答案：触发链会放大一次语句的影响，可能形成递归、顺序依赖、性能抖动或难以解释的回滚范围；B 失败还可能使原语句整体失败。应限制链路和递归，明确事务边界及执行顺序，记录依赖关系，优先把可见业务流程放在显式服务中，并用失败和批量场景测试
