将访问需求与通常更适合优先评估的结构匹配

正确答案：高选择性等值与范围查询并存 → B+ 树索引；主要为高选择性等值查询 → 哈希索引；低基数、读多写少且常组合筛选 → 位图索引；返回表中大部分记录 → 顺序扫描

索引选择要结合查询类型、选择性、数据规模、读写比和空间，而不是只看单次查找速度

第 2 题 / 共 7 题 · 排序题

按 B+ 树等值查找的路径排列

  1. 到达叶结点定位索引项
  2. 在中间结点继续缩小键值范围
  3. 通过记录指针读取目标记录或判断不存在
  4. 从根结点比较搜索键并选择子指针

正确答案：从根结点比较搜索键并选择子指针 → 在中间结点继续缩小键值范围 → 到达叶结点定位索引项 → 通过记录指针读取目标记录或判断不存在

平衡多级结构使所有叶结点深度相同，查找 I/O 随树高增长而不是随记录数线性增长

第 4 题 / 共 7 题 · 匹配题

将 B+ 树更新情况与维护动作匹配

正确答案：叶结点插入后溢出 → 分裂结点并把分隔键传播到父结点；删除后结点低于占用要求 → 向兄弟借键或合并并调整父结点；修改索引键 → 通常按旧键删除、按新键重新插入

分裂、借位和合并用于保持树平衡，但会增加写入和并发控制成本

第 5 题 / 共 7 题 · 匹配题

将哈希查找现象与处理方式匹配

正确答案：目标桶中直接找到键 → 返回对应记录指针；目标桶已满并发生冲突 → 继续检查溢出页或溢出链；检查目标桶及溢出链仍无键 → 判断该键不存在；数据规模长期增长 → 重组静态哈希或采用可动态扩展的哈希结构

哈希把键映射到桶，冲突和增长策略决定查找长度与维护成本

第 6 题 / 共 7 题 · 多选题

关于位图索引，下列哪些说法正确？

正确答案：每个低基数取值可以对应一个位向量、AND 可组合同时满足多个条件的记录、OR 可组合满足任一条件的记录、位计数可快速估计命中数量、频繁单行更新可能带来维护和并发成本

位图擅长低基数分析筛选，得到记录位置后仍可能需要回表读取其他列

一个订单表既有 OrderId 等值查询、OrderTime 范围查询，又常按少量状态组合统计。如何组合索引并说明边界？

对照答案：OrderId 可用 B+ 树或哈希支持高选择性等值定位；OrderTime 更适合 B+ 树及叶链范围扫描；状态若基数低、读多写少，可评估位图索引并用位操作组合。若订单持续高频更新，位图维护与并发成本可能过高。最终还要比较选择性、覆盖列、回表 I/O、空间和优化器实际计划，不能保证每个查询都使用索引
