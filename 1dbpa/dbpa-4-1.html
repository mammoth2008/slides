ACCESS CONTROL

GRANT 把指定权限授予指定用户或角色

一条 GRANT 同时确定权限、对象和接收者

U1、U4 是课堂账号；实际账户写法按目标 DBMS 手册确定

SQL
01
02GRANT SELECT ON TABLE Student TO U1;
GRANT UPDATE(Smajor), SELECT ON TABLE Student TO U4;
Takeaway

这里的 SELECT 允许查询整张表，UPDATE(Smajor) 只允许修改专业列；若只准访问某些行，还要用视图或按用户身份筛选。写入的数据仍须满足完整性约束

08-- DBA → U5

-- U5 → U6
GRANT INSERT ON TABLE SC TO U6 WITH GRANT OPTION;
-- U6 → U7
GRANT INSERT ON TABLE SC TO U7;
-- 收回 U5 传播出的权限
REVOKE INSERT ON TABLE SC FROM U5 CASCADE;
Takeaway

用户获得对象权限时，只有附带 WITH GRANT OPTION 才能再授给别人；收回权限的语法要查所用 DBMS。若用户还从别处获得同一权限，就可能继续保有它

PROPAGATION AND REVOKE
DBPA | CH04 | 4.1 | 4.2

把同一岗位的权限放进角色，再分给多人

先授岗位权限给角色，再授角色给任职者；账号与角色激活规则须查 DBMS

SQL
01
02
03
04CREATE ROLE R1;
GRANT SELECT, UPDATE, INSERT ON TABLE Student TO R1;
GRANT R1 TO 王平, 张明, 赵玲 WITH ADMIN OPTION;
REVOKE R1 FROM 王平;
Takeaway

WITH GRANT OPTION 允许把对象权限再授给别人，WITH ADMIN OPTION 允许管理角色的授予和回收；角色如何激活要查所用 DBMS

10/17
ROLES
DBPA | CH04 | 4.1 | 4.2

DAC：有授权资格的人决定谁能做什么

对象所有者或持有转授权资格的人，可以允许别人对指定对象执行某种操作

谁决定

DBA、对象属主，或拥有该权限及 WITH GRANT OPTION 的用户可以作出授权决定

决定什么

决定用户对对象可以执行哪些具体操作

可能出错

权限可能沿转授权继续传播，也可能授给了不该获得的人

Takeaway

DAC 检查用户是否有权执行操作，完整性检查判断数据是否符合规则；若系统同时采用 MAC，通过 DAC 后还必须满足密级规则

11/17
DAC
DBPA | CH04 | 4.1 | 4.2

MAC：系统再比较主体许可证与客体密级

即使某人拿到了普通授权，只要读写不满足密级规则，系统仍会拒绝

概念含义例子
主体发起访问用户或进程
客体被访问表、视图或文件
密级标记主体许可证／客体密级主体 S 级／客体 C 级
Takeaway

系统按密级强制执行 MAC，用户不能用普通 GRANT 绕过它；系统比较主体许可证级别与客体密级，判断能否读写

MAC LABELS
DBPA | CH04 | 4.1 | 4.2

MAC 防止高密级信息写入低密级对象

规则条件结果

MAC EXAMPLES
DBPA | CH04 | 4.1

四个请求：查什么、结果怎样、还缺什么

先写主体、操作、对象和授权来源，再判结果；审计另记时间、账号和结果

请求一：学生查 Student

学生已登录但请求整表 SELECT：检查该学生是否有查询权限，以及是否需要限制为只看自己的记录；登录成功本身不足以放行

请求二：教师改成绩

T17 请求 UPDATE SC.Grade：检查有效角色、列级权限和数据完整性；三者回答不同问题

请求三：U7 继续插入

U5 的授权被回收后 U7 仍请求 INSERT SC：查清权限经谁转授、收回时会影响谁，以及 U7 是否还从别处获得同一权限

请求四：S 写入 C

即使 DAC 已允许，主体 S 写入客体 C 仍被 MAC 拒绝，以阻止高密级信息向下流动
