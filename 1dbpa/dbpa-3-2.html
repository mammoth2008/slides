DBPA | CH03 | 3.2 | 3.2.2

不同数据类型

先列出允许的值、最大长度或精度，以及后续是否比较、求和或计算平均值

字符

CHAR(n) 适合定长值，VARCHAR(n) 适合长度变化的文本

数值

SMALLINT、INT、BIGINT 和 DECIMAL(p,s) 适合不同范围与精度

时间

DATE、TIME 和 TIMESTAMP 支持时间相关比较和运算

设计时要写成“数据类型 + 长度/精度 + 必要的完整性约束”

Takeaway

正式执行前需要核对目标 DBMS 和版本支持的类型名称与范围

删除对象时必须先处理依赖关系

RESTRICT 与 CASCADE 的含义取决于正在删除或修改的对象

对象操作RESTRICTCASCADE
DROP SCHEMA模式中已有对象时拒绝连同模式内对象一起删除
DROP TABLE被外码、视图等依赖时拒绝可能删除依赖对象或依赖定义
DROP COLUMN / CONSTRAINT被其他定义引用时拒绝可能移除依赖的视图、约束或其他定义
Takeaway

不要把 CASCADE 当作默认选项

索引提供额外的存取路径

索引是常见 RDBMS 扩展：查询可能受益，但会增加空间与更新成本

SQL
01
02CREATE INDEX Idx_StuSname

建立

CREATE INDEX 在表的一列或多列上建立索引，提供额外的存取路径

修改

ALTER INDEX 可按目标 DBMS 支持的语法重命名或调整索引

删除

DROP INDEX 删除不再需要的索引；系统也会从数据字典移除其定义

Takeaway

RDBMS 根据条件、统计信息和可用路径决定是否使用索引

DBPA | CH03 | 3.2 | 3.2.3

哪些表适合建立索引？

建立索引要看查询频率、选择性和更新成本

收益

高频且高选择性的查询条件更可能受益，例如按唯一订单号定位唯一一条记录

成本

低选择性或元组数量较少的表，收益可能有限；频繁更新的状态列还会增加维护成本

责任

DBA 或表属主提出候选索引，DBMS 依据统计信息决定是否使用；普通索引不自动增加唯一性约束

如果表很小、更新很频繁，还值得建索引吗？
