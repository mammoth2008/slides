给中间结果起了名字，DBMS 就一定先物化它并加速查询吧？

08WITH class_avg AS (
  SELECT TeachingClass, AVG(Grade) AS avg_grade
  FROM SC
  WHERE TeachingClass IN ('81001-01', '81001-02')
  GROUP BY TeachingClass
)
SELECT MAX(avg_grade) - MIN(avg_grade) AS difference
FROM class_avg;
命名中间结果→同一语句内引用→语句结束后名称失效
Takeaway

WITH 的结果只在当前语句中有效；它不创建长期表，也不保证一定物化或提速

递归 CTE 的查询骨架

种子查询给出首层，递归项持续扩张，直到不再产生新行

07WITH RECURSIVE prereq(cno) AS (
  SELECT Cpno FROM Course WHERE Cno = '81003'
  UNION [ALL]
  SELECT c.Cpno FROM Course c
  JOIN prereq p ON p.cno = c.Cno
)
SELECT cno FROM prereq;

该骨架只表达递归语义，不是可直接执行的产品脚本。UNION 通常去重，UNION ALL 保留重复；示例没有环，多路径和环需要额外的去重、深度或访问边界策略

GPA 计算同时需要判断和累加

过程化逻辑把每门课程的处理步骤串起来

GPA=总学分绩点 ÷ 总学分
成绩：85、96、87→绩点：3、4、3→学分：4、4、4 GPA=(3×4+4×4+3×4) / 12=3.33
步骤处理状态
处理处理一门有效课程的成绩和学分逐门处理的状态模型
判断按分数段得到绩点课程绩点
累加计算总学分绩点和总学分两个总量
返回总学分大于 0 时计算 GPA输出结果

DBPA | CH08 | 8.1 | 8.2

异常处理：说明业务后果与事务边界

已经捕获异常，数据库就会自动回滚吧？

异常处理决定如何响应错误；是否回滚取决于事务边界、提交点和目标 DBMS

捕获

识别异常，或让异常向上层传播

判断

判断能否继续、记录、重试或终止

处理

按业务规则处理；回滚不是捕获异常后的必然动作

总学分为 0→GPA 无法计算→返回提示或 NULL，不等于自动回滚；约束冲突→写入失败→记录、传播或按事务策略撤销修改
Takeaway

NULL 或 UNKNOWN 可能只改变分支结果，不一定产生异常；异常捕获、业务响应和事务回滚是三个不同判断
