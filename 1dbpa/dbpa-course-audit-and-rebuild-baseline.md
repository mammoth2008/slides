检查日期: 2026-07-04
课程: DBPA
源目录: `draft/dbpa/`
目标目录: `1dbpa/`
审查范围: 1dbpa/dbpa-*.html, draft/dbpa/*.md, mindmap, navigation, layout, resources
审查状态: draft

## 一句话结论

当前 `1dbpa/` 下的 HTML 可以作为旧课件参考, 但不能直接作为下学期课件生成基础。主要原因是: `draft/dbpa/` 中正文 md 大量缺失, `dbpa-0.html` 总目录与现有分节 HTML 已经发生语义错位, 多个现有 HTML 存在导航、布局、资源或标题问题。

后续工作应先恢复和重建 `draft/dbpa/*.md`, 再重新生成 HTML、重做 layout 和 `cXXq` 导航。

本文档不只是情况总结, 也是后续 DBPA 课程重建工作的基线文件。后续每一轮重建应回到这里更新决策、完成状态和仍未解决的问题。

## 关键风险清单

- `draft/dbpa` 中正文 md 大量缺失, 不能直接稳定重生成。
- `dbpa-0.html` 总目录与现有 HTML 语义错位。
- 多个页面存在导航、mindmap、资源或布局问题。
- 课程目标、贯穿案例、评价链路仍需先行裁决。

## 审查过程复盘

本轮审查主要做了工程层面的事实扫描:

- 对比 `1dbpa/` 现有 HTML 和 `draft/dbpa/` 源稿
- 检查总目录链接是否落地
- 读取各分节 HTML 的标题、导航页、mindmap、图片引用和 step id
- 标出明显的章节语义错位、重复 id、缺失资源和导航错误
- 用现有布局规则判断一部分重叠、锚点和旧式坐标问题

这套检查适合回答“当前文件能不能作为生成基础”, 但还不能完整回答“这门课是否是一门好课”。后续重建时, 还需要补上课程设计层面的审查。

## 高阶课程设计问题

如果由顶级软件架构师和课程设计师审查, 他们大概率会继续追问以下问题。

### 课程目标是否重新定义

当前文件检查发现的是目录和课件资产问题, 但尚未确认下学期 DBPA 的课程目标。需要明确这门课到底要训练学生:

- 理解数据库系统基本概念
- 掌握关系模型和 SQL
- 完成数据库设计与实现
- 理解事务、恢复、并发、安全等系统机制
- 能在 AI 辅助环境下分析、建模、查询和解释数据

如果课程目标不先定, 目录修复会变成“把旧课件补齐”, 而不是“为下一轮教学重建课程”。

### 章节结构是否仍然合理

旧目录接近传统数据库教材目录, 但当前现有 HTML 已经把恢复、并发、技术进展等内容移动过。顶级审查不会只问“文件是否缺失”, 而会问:

- 是否还需要完整保留传统第 8-13 章
- 恢复和并发是否应该作为压缩专题放在设计与 SQL 之后
- 王者荣耀数据库案例是否应成为贯穿案例, 而不是只出现在 3.2
- 数据库设计、SQL 和事务机制之间是否形成递进闭环

因此 `dbpa-0.html` 不应只按旧目录修链接, 而应先重画课程结构。

### 学生画像和课时约束尚未进入审查

现有扫描没有纳入:

- 学生专业背景
- 学生编程和 SQL 基础
- 本课程总课时和每章课时
- 是否包含实验课、作业、课程项目
- 是否服务考核、竞赛、毕业设计或实际业务数据分析

没有这些约束, 很难判断某一节“内容太长”还是“必要展开”。

### 案例资产需要课程级评估

`dbpa-3-2.html` 的“王者荣耀数据库”是有价值的贯穿案例资产, 但仍需评估:

- 是否适合所有学生
- 是否需要换成更稳定、更通用的业务场景
- 是否存在版权、品牌或课堂接受度风险
- 是否能贯穿建模、SQL、完整性、设计、事务和优化

如果保留, 后续应把它上升为全课程案例数据库, 而不是一节中的局部示例。

### 评价设计尚未建立

当前 `dbpa-exec.html` 和 quiz 页存在, 但本轮没有深入审查练习题质量。后续需要检查:

- 练习是否覆盖每节核心目标
- 题目是否只是回忆概念, 还是要求建模、写 SQL、解释结果
- 是否存在课程项目或阶段性产出
- 是否能用同一个案例数据库形成连续任务

课程重建不能只恢复 slides, 还要同步恢复“学完之后学生能做什么”的证据链。

### 生成链路缺少可验证契约

顶级架构师会认为当前最大风险不是某个页面坏了, 而是缺少清晰的生成契约:

- 哪些文件是源
- 哪些文件是生成物
- 哪些 HTML 允许手改
- 哪些资源必须由 md 引用
- 每次生成后如何验证导航、布局、资源、练习页
- 总目录如何从课程结构同步更新

本项目已有 `slides-workflow` 规则, 但 DBPA 这门课需要把规则落到一份课程级重建清单中。

### 视觉和课堂节奏尚未审查

本轮没有打开浏览器逐页观看, 也没有从投影环境评价:

- 字号是否适合教室
- 图片是否清楚
- 一页信息量是否过高
- 3D 路径是否帮助理解, 还是增加认知负担
- 关键概念是否有足够结构图

因此布局问题记录只是最低限度的工程检查, 不能替代课堂可读性审查。

### 内容时效性和工具环境尚未审查

SQL、MySQL、客户端工具、安装截图、数据库发展趋势、内存数据库、区块链、大数据等内容都可能过时。后续需要检查:

- MySQL 版本和安装流程是否仍适用
- 截图是否来自旧版本工具
- 数据库技术进展是否需要加入云数据库、向量数据库、HTAP、Lakehouse 等内容
- AI 辅助 SQL、自然语言查询和数据建模是否应进入下学期课程

这部分不能只靠本地文件判断, 需要在具体改课时另行查证。

## 重建前必须先做的决策

在开始恢复正文 md 前, 建议先做四个决策:

1. 确定下学期 DBPA 的章结构: 沿用传统教材目录, 还是压缩为教学专题
2. 确定贯穿案例: 保留王者荣耀数据库, 替换为业务数据案例, 或两者并用
3. 确定恢复策略: 是逐节从 HTML 反向生成 md, 还是先重写课程大纲再吸收旧素材
4. 确定评价链路: 每章是否同步产出练习、实验或项目任务
