4/19
ONE REQUEST
DBPA | CH01 | 1.5 | 1.5.1

集中式：主要组件在同一台计算机

应用、DBMS 和数据库在同一台计算机上，可被多个终端共享

查看成绩：应用程序+DBMS+数据库→同一台计算机

单用户

微型计算机上的数据库系统通常由一个用户使用，如 SQLite

多用户

小型机或大型机上的数据库系统可以让多个终端共享同一个系统

应用、DBMS 和数据库是否集中在一台计算机；接入多少终端不重要

Takeaway

少了跨机器请求，但 CPU、内存、存储和故障的影响也会集中

5/19
CENTRALIZED DATABASE SYSTEM
DBPA | CH01 | 1.5 | 1.5.2

客户端/服务器体系

客户端应用通过网络向服务器上的 DBMS 请求数据

请求路径：客户端应用 → 服务器上的 DBMS → 服务器上的数据库

返回路径：数据库 → 服务器上的 DBMS → 网络 → 客户端应用

客户端

提供用户界面和部分业务数据处理流程，需要数据时发出请求；桌面应用、移动应用或浏览器都是客户端

服务器

通过网络接收请求，处理数据库访问，把用户需要的数据通过网络链路返回给客户端

Takeaway

多台终端可以共享数据库服务；会有网络断开、身份认证和连接管理问题

如果增加应用服务器，请求路径会怎样变化？

6/19
CLIENT-SERVER DATABASE SYSTEM
DBPA | CH01 | 1.5 | 1.5.2

客户端/应用服务器/数据库服务器三层结构

浏览器先访问应用服务器，应用服务器再请求数据库服务器

浏览器→应用服务器→数据库服务器

浏览器

提供统一的用户界面，发出业务请求。应用在浏览器中运行

应用服务器

检查登录和业务规则，组织要发给数据库服务器的请求

数据库服务器

运行 DBMS 和数据库，读写数据并执行事务、权限和完整性检查

Takeaway

客户端、应用服务器、数据库服务器职责不同

C/S 结构和 B/S 结构

桌面或移动应用可以直接作为客户端；B/S 使用浏览器作为客户端

8/19
CS AND BS COMPARISON
DBPA | CH01 | 1.5 | 1.5.2

数据请求的往返

两层结构让客户端直接连接数据库，三层结构让应用服务器承担部分业务处理

结构请求路径返回路径主要职责
两层Client → DB ServerDB Server → Client客户端直接请求数据服务
三层Client → App Server → DB ServerDB Server → App Server → Client应用服务器检查登录和业务规则，组织数据库请求

C/S 不一定都是两层，B/S 也不一定都是三层

Takeaway

三层结构集中处理登录和业务规则，也多了一层网络往返和故障排查

9/19
REQUEST PATH
DBPA | CH01 | 1.5 | 1.5.3

并行数据库：同一任务并行处理

一个查询可以拆给多个处理单元，再汇总结果

查看成绩（教务汇总）：分解→并行处理→汇总结果
结构资源如何共享
共享内存型多个处理器共享同一片内存
共享磁盘型多个处理器共享磁盘，协同访问数据
非共享型各处理单元拥有自己的处理器、内存和磁盘，通过系统协作
混合型组合不同共享方式，按系统需要组织处理资源
Takeaway

适合的查询可能更快，但系统还要拆分、调度和汇总任务

10/19
PARALLEL DATABASE SYSTEM
DBPA | CH01 | 1.5 | 1.5.4

分布式：数据分布在不同位置

数据跨多个网络节点，用户仍可将其看作一个逻辑整体

多校区：各校区维护本地成绩→教务处跨校区汇总
观察点具体含义
逻辑整体多个节点上的数据在逻辑上仍作为一个数据库
场地自治节点可以独立处理本地数据库
局部应用独立访问和处理本地节点的数据
全局应用通过网络访问和处理多个节点的数据
Takeaway

分布式数据要跨网络节点，同时每个节点也可以处理本地数据

11/19
DISTRIBUTED DATABASE SYSTEM
DBPA | CH01 | 1.5 | 1.5.5

云数据库：通过网络使用数据库服务

应用通过网络使用云环境中的数据库，不必自己部署全部服务器和 DBMS

考试周选课高峰：调用云数据库服务 → 按需获得资源 → 返回结果

服务交付

应用连接数据库服务后，可以存储、更新和查询数据，由服务处理事务

弹性资源

考试周可以增加计算和存储资源，访问量下降后再缩减

共同责任

云服务分担部分基础设施运维；用户仍需管理数据、权限、安全与成本

Takeaway

“云”说明服务的获得方式，而不是服务内部的技术

用了云服务，数据和权限责任也一起外包了吗？

CLOUD DATABASE SYSTEM
DBPA | CH01 | 1.5

并行、分布式和云数据库比较

不同结构改变了什么？该如何判断？

体系结构判断依据得到什么好处多处理什么问题
并行一个任务使用多个处理单元提高适合查询的处理速度拆分、汇总和资源竞争
分布式数据和处理跨多个网络节点，节点可以自治为就近处理、增加节点和故障接替提供条件网络故障、一致性和节点管理
云数据库数据库能力按网络服务提供按需资源和减少部分基础设施运维服务依赖、隐私、成本和管理责任
Takeaway

同一个云数据库可以跨节点保存数据，也可以让多个处理单元并行执行查询
