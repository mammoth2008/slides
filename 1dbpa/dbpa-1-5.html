4/19
ONE REQUEST
DBPA | CH01 | 1.5 | 1.5.1

集中式：主要组件在同一台计算机

应用、DBMS 和数据库集中在同一台计算机内，可被多个终端共享

查看成绩：应用程序+DBMS+数据库→同一台计算机

单用户

微型计算机上的数据库系统通常由一个用户使用，如 SQLite

多用户

小型机或大型机上的数据库系统可以让多个终端共享同一个系统

关键看应用、DBMS 和数据库是否分别放置在不同的物理计算机上

Takeaway

集中式减少跨机器通信，但资源、扩展能力和故障影响也更集中

5/19
CENTRALIZED DATABASE SYSTEM
DBPA | CH01 | 1.5 | 1.5.2

客户端/服务器体系

客户端应用通过网络向服务器上的 DBMS 请求数据

请求路径：客户端应用 → 服务器上的 DBMS → 服务器上的数据库

返回路径：数据库 → 服务器上的 DBMS → 网络 → 客户端应用

客户端

提供用户界面和部分业务数据处理流程，需要数据时发出请求；桌面应用、移动应用或浏览器都是客户端

服务器

通过网络接收请求，处理数据库访问，把用户需要的数据通过网络链路返回给客户端

Takeaway

把应用和数据库分到客户端与服务器，但增加网络、认证和连接管理负担

如果增加应用服务器，请求路径会怎样变化？

6/19
CLIENT-SERVER DATABASE SYSTEM
DBPA | CH01 | 1.5 | 1.5.2

客户端/应用服务器/数据库服务器三层结构

浏览器可以视为一种客户端的使用方式

浏览器→应用服务器→数据库服务器

浏览器

提供统一的用户界面，发出业务请求

应用服务器

运行应用系统或模块，承接业务逻辑

数据库服务器

运行 DBMS 和数据库，处理数据访问、事务和控制

Takeaway

三层部署结构和三级模式结构都是“三层”，但注意区别

THREE-TIER STRUCTURE
DBPA | CH01 | 1.5 | 1.5.2

C/S 结构和 B/S 结构

客户端是请求方，浏览器是一种客户端运行环境

Takeaway

C/S 交互直接、客户端能力更强，但客户端更新与连接安全管理任务更重；B/S 便于统一部署和维护，但增加应用负担、网络往返和复杂性

8/19
CS AND BS COMPARISON
DBPA | CH01 | 1.5 | 1.5.2

请求在两层和三层结构中怎样往返

两层结构让客户端直接连接数据库，三层结构让应用服务器承担部分业务处理

结构请求路径返回路径主要职责
两层Client → DB ServerDBS → C客户端直接请求数据服务
三层Client → App Server → DB ServerDBS → AS → C应用服务器承接业务逻辑

C/S 不一定都是两层，B/S 也不一定都是三层

Takeaway

是否架设单独的应用服务器，取决于业务复杂程度和访问量

9/19
REQUEST PATH
DBPA | CH01 | 1.5 | 1.5.3

并行数据库：同一任务并行处理

一个查询可以拆给多个处理单元，再汇总结果

查看成绩（教务汇总）：分解→并行处理→汇总结果
结构资源如何共享
共享内存型多个处理器共享同一片内存
共享磁盘型多个处理器共享磁盘，协同访问数据
非共享型各处理单元拥有自己的处理器、内存和磁盘，通过系统协作
混合型组合不同共享方式，按系统需要组织处理资源
Takeaway

并行使任务可以同时处理，带来性能、可用性和扩展性，但需要协调成本

10/19
PARALLEL DATABASE SYSTEM
DBPA | CH01 | 1.5 | 1.5.4

分布式：数据分布在不同位置

数据跨多个网络节点，用户仍可将其看作一个逻辑整体

多校区：各校区维护本地成绩→教务处跨校区汇总
观察点具体含义
逻辑整体多个节点上的数据在逻辑上仍作为一个数据库
场地自治节点可以独立处理本地数据库
局部应用独立访问和处理本地节点的数据
全局应用通过网络访问和处理多个节点的数据
Takeaway

数据物理跨网络节点并允许节点自治

11/19
DISTRIBUTED DATABASE SYSTEM
DBPA | CH01 | 1.5 | 1.5.5

云数据库：数据库能力上云

云数据库在云环境中部署，通过网络提供数据库能力

考试周选课高峰：调用云数据库服务 → 按需获得资源 → 返回结果

服务交付

用户获得存储、更新、查询处理和事务管理，不必自己部署全部基础设施

弹性资源

云环境可以根据负载变化分配计算资源和存储资源

共同责任

云服务分担部分基础设施运维；用户仍需管理数据、权限、安全与成本

Takeaway

云数据库是能力视角，底层依然使用并行/分布式技术

用了云服务，数据和权限责任也一起外包了吗？

CLOUD DATABASE SYSTEM
DBPA | CH01 | 1.5

并行、分布式和云数据库比较

改变了什么？该如何命名？

体系结构核心变化获得的能力新增问题
并行一个任务使用多个处理单元提高适合查询的处理速度拆分、汇总和资源竞争
分布式数据和处理跨多个网络节点，节点可以自治就近处理、扩展性和可用性网络故障、一致性和节点管理
云数据库数据库能力按网络服务提供按需资源和减少部分基础设施运维服务依赖、隐私、成本和管理责任
Takeaway

并行、分布式、云三种体系并非严格隔离

CHAPTER BOUNDARY

按变化维度判断体系结构

组件位置、请求路径和协作负担共同决定体系结构判断

集中式与客户-服务器

集中式把主要组件放在一台计算机

客户-服务器把应用与数据库服务分开

并行与分布式

并行把一个任务交给多个处理单元

分布式让多个节点处理本地或全局数据

云数据库

云数据库以网络服务提供存储、查询和事务能力

用户仍需处理安全、隐私、成本和责任

Takeaway
