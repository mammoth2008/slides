将负载类型与主要特征匹配

正确答案：OLTP → 短事务、高并发、更新频繁并强调一致提交；OLAP → 面向历史主题数据进行长查询、聚集和分析；HTAP → 在同一体系中同时服务较新事务数据和分析请求

事务数据进入独立分析环境的一般数据链如何排列？

  1. 装载到面向主题和历史的分析存储
  2. 清洗、转换并统一业务口径
  3. 从事务源抽取或捕获变化
  4. 构建聚集、报表或模型并监视新鲜度

正确答案：从事务源抽取或捕获变化 → 清洗、转换并统一业务口径 → 装载到面向主题和历史的分析存储 → 构建聚集、报表或模型并监视新鲜度

ETL／ELT 的具体顺序可不同，但都要处理数据口径、质量、延迟和回溯边界

第 3 题 / 共 7 题 · 匹配题

将关系扩展方向与主要能力匹配

正确答案：面向对象数据库 → 直接持久化复杂对象、继承和对象标识；对象关系数据库 → 在关系与 SQL 基础上增加用户定义类型和复杂对象能力；XML 数据管理 → 支持半结构化交换、层次文档和异构集成

三条路线扩展的数据表达和接口不同，不能都简化为“比关系表更灵活”

第 4 题 / 共 7 题 · 匹配题

将数据库路线与典型取向匹配

正确答案：SQL 关系数据库 → 稳定模式、关系查询和边界清晰的 ACID 事务；NoSQL → 按键值、文档、列族或图等模型为特定扩展负载取舍；NewSQL → 尝试在分布式节点上保留 SQL 与强事务能力

路线选择要看数据模型、接口、事务范围、一致性和扩展代价，不是按名称排序

第 5 题 / 共 7 题 · 匹配题

将分布式机制与主要目标匹配

正确答案：分片 → 把数据和请求分布到多个节点以扩展容量和吞吐；副本 → 保存同一数据的多个拷贝以提高读取能力或可用性；横向扩展 → 通过增加节点扩展系统资源；共识／协调 → 在多个副本或分片事务之间维持接受顺序和一致状态

分片与副本解决不同问题，并都会引入路由、同步、故障和协调成本

BASE 是否意味着 NoSQL 系统完全不关心一致性？

正确答案：不是，BASE 强调可用性和状态逐步收敛等取舍，仍需定义一致性边界

一致性不是有或无的单一开关，要说明读取、写入、复制和冲突解决的具体保证

第 7 题 / 共 7 题 · 回想题

一个系统同时有订单扣库存、海量行为事件和跨区域 SQL 交易。怎样初步组合 SQL、NoSQL 与 NewSQL 路线？

对照答案：订单扣库存需要清晰 ACID 边界，可使用关系数据库；海量事件若模式变化大、按键或时间写入为主，可评估相应 NoSQL 模型；若跨区域事务仍要求 SQL、强一致和横向扩展，可评估 NewSQL。还要设计数据同步、重复事实来源、跨系统事务、延迟和治理，不能把三套系统简单叠加后假定能力自动相加
