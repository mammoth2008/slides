# DBPA 7.3 设计与试运行练习包

本包承接 7.1 课堂需求样本与 7.2 完整 E-R 图。SQL 固定以 MySQL 8.4 / InnoDB 为语法参考；实际课堂先记录 `SELECT VERSION()` 和引擎。尚未在本机执行 MySQL。独立 SQLite 模型验证只覆盖关系与约束语义，不替代 MySQL 的运行和性能证据。

## 先完成小样本

1. 选择新建的空练习数据库，执行 `00-schema.sql`，再执行 `01-small-sample.sql`
2. 核对 Student=2、Course=2、Teacher=2、TeachingClass=3、SC=3。C001/2026-1/01、C002/2026-1/01、C001/2026-2/01 必须同时存在
3. `02-constraint-cases.sql` 中失败语句逐条执行并保留错误。重复、未知班、未知学生和130分都应拒绝，原SC三行不变；1:1扩展须拒绝同一教师兼任两院院长
4. 执行 `03-queries.sql`，核对文件注释中的两组具体结果
5. 可选执行 `06-evaluation-extension.sql`。T01看到“讲解清楚／希望增加演示”，T02看到“实验充分”；教师视图列中无Sno、Sname。两名学生分别看到本人2条、1条评价及反馈

四个固定用户视图只是显示范围样例。实际授权要将对应视图分配给对应账户、限制基本表与其他用户视图的访问，再分别以实际账户验证；不能用管理员查询成功代替权限测试。评价自由文本可能暴露身份，隐藏标识列不等于保证完全匿名。

## 再准备代表性大样本

在另一个空练习库中执行 `00-schema.sql`，不要先导入小样本。用 `python3 generate-load.py --output load.sql` 生成 SQL，再导入此库。输出路径必须尚不存在，防止覆盖已有文件。

默认生成3万学生、500课程、2名合成教师、每课每学期8班，每班50条SC，容量80。三个学期为2025-1、2025-2、2026-1，合计12000教学班、60万SC；每学期20万条。所有数据为均匀合成值，不是学校实际记录。正式评价还应加入真实业务允许的偏斜与热点。

身份：TeachingClass主码(Cno,Term,ClassNo)，SC主码(Sno,Cno,Term,ClassNo)，SC必须完整引用班。字段格式依需求样本；本包只演示数据与关键约束，不实现资格、开放期或容量并发检查。

## 比较 A、B、C

- A：保留主码及引擎为外码要求或自动建立的索引。先运行 `07-explain.sql`，保存实际已有索引与计划
- B：从同一数据快照恢复，在A上执行 `04-index-B.sql`
- C：从同一快照恢复，在A上依次执行 `04-index-B.sql`、`05-index-C.sql`
- 对每个方案保存实际计划中的索引、估计扫描行数与覆盖情况；不要预填“必然使用某索引”

课堂可固定预热60秒、测量600秒，并记录硬件、引擎、并发数、缓存状态和数据快照。成绩查询40次/秒、名单查询10次/秒、写入尝试峰值100次/秒是需求假设；若测最大成功插入能力，要另做饱和负载试验，明确其与100次/秒固定到达率试验的区别。课件135/118/85是容量上限的假设结果，不是在每秒仅发送100个请求时测得的完成量。表中的查询p95也假定在各方案对应稳定写入上限附近取得；固定读请求为40/10次每秒。实际验收还要测每秒100次写入的目标负载，不能将C在85次上限附近的低查询延迟当作目标负载已经通过。

写入测试使用当前学期、仍有余量的班，分配尚未选过该班的学生；确保测试请求本身合法。记录成功插入、业务拒绝和系统错误，不把拒绝请求计成成功写入。不足容量时准备更大的空余量或缩短持续时间，并在各方案保持相同条件。每轮恢复相同快照，避免上一轮插入污染下一轮。

`actual-measurements.csv` 的实测栏保持待填；`teaching-assumptions.csv` 全为虚构判断练习。p95指95%的请求时延不超过该值。查询目标为p95≤2000ms；合法写入容量至少100次/秒。教学假设中C只有85，应淘汰；A/B均达标，B额外14MiB是否值得，要结合名单查询收益决定。

SC索引空间的测量必须注明引擎统计口径，尤其是否包含聚簇主码数据；三方案同口径比较。副本、日志和备份容量另列，不混入这个字段。

## 联合调试与恢复

- 功能：从39/40名额接受一人后到40；重复申请或满额拒绝；两个并发请求抢最后一位时最多一个成功
- 权限：学生仅本人；教师仅本人所教班。实际身份校验、授权与事务由应用实现并测试
- 恢复：在隔离练习库中还原备份与必要日志，记录恢复点、耗时、行数、关键记录和约束结果，核对已提交事务
- 不合格时回到数据映射、应用／逻辑、物理或恢复方案，修正后重测同一场景

本包不会连接现有数据库、创建用户或修改真实系统；也不把创建表成功当作完整选课系统已经完成。
