谁建连接、谁执行 SQL、谁逐行读结果

DataSource 取连接，Connection 管事务，语句执行，ResultSet 读行后关闭

API主要职责常见调用

Takeaway

6/18
EXECUTION METHODS
DBPA | CH08 | 8.3 | 8.3

JDBC 请求：连接、执行、读取、释放

成功路径能完成查询，还要证明异常路径会释放资源

无论成功或报错，按 ResultSet → Statement → Connection 逆序关闭或归还

  1. 01加载：发现或注册目标 DBMS 的驱动
  2. 02连接：构造 URL 或使用 DataSource，获取 Connection
  3. 03执行：创建语句对象，绑定参数并执行查询、更新或过程调用
  4. 04处理：读取 ResultSet、更新行数或过程输出，并执行业务逻辑
  5. 05释放：按 ResultSet → Statement → Connection 逆序关闭或归还
Takeaway

JDBC 4 以后驱动可能由服务机制自动发现；任一步异常都要进入资源释放路径，try-with-resources 可覆盖成功和异常路径

JDBC WORKFLOW
DBPA | CH08 | 8.3 | 8.3

参数绑定和类型映射是两个方向

输入值进入 SQL，查询结果再回到 Java 变量

输入：?→setXXX()→SQL 参数 输出：ResultSet→next()→getXXX()→Java 变量
方向负责什么边界
参数绑定把 Java 值按类型传给 ?不拼接 SQL 结构
类型映射在 SQL 类型与 Java 类型间转换选择匹配的 setXXX／getXXX
结果读取移动游标并读取当前行先 next()，再 getXXX()
Takeaway

参数化可降低 SQL 注入风险，但不替代权限、业务校验和事务控制

DAO 集中 SQL，ORM 映射对象与表

用了 ORM，事务、权限和查询性能也会自动处理吗？

它们减少重复 JDBC 或 CRUD 代码，但不决定事务、权限或查询速度

DAO

ORM

映射关系、列与业务对象，减少手写常规 CRUD SQL

两条数据路径：Model → DAO → JDBC → DBMS；或 Model → 持久层／DAO → ORM → DBMS

Takeaway
