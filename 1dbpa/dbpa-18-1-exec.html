第 1 题 / 共 7 题 · 匹配题

将区块链系统中的对象与主要职责匹配

正确答案：链式数据结构 → 用哈希引用连接区块历史，使已接受记录的改动可检测；分布式账本 → 由多个节点保存并验证共同接受的历史副本；共识机制 → 按协议决定接受哪一段历史及其状态结果；节点状态数据库 → 执行账本记录后维护本地可查询的派生状态

四类对象相互配合但不能混为一谈；有哈希链并不自动具备分布式账本和共识

第 2 题 / 共 7 题 · 匹配题

将比特币式区块组成与其作用匹配

正确答案：父区块哈希 → 把当前区块接到上一段已接受历史；Merkle 根 → 承诺区块体中的交易集合；Bits 与 Nonce → 为工作量证明提供难度目标和试探字段；区块体 → 保存本区块收录的交易记录

区块头保存链接和协议证据，区块体保存交易；具体字段会随协议变化

第 3 题 / 共 7 题 · 多选题

某个已接受区块中的一笔交易被修改后，哪些变化可以让节点检测到历史不一致？

正确答案：该交易沿 Merkle 树计算出的根会变化、区块头变化会使该区块哈希变化、后继区块保存的父哈希将不再匹配、修改者必须重做后续区块所要求的协议证明并使网络接受新历史

哈希承诺使改动可检测并增加重写成本，但交易合法性仍由协议验证，不能把它表述为绝对不可修改

第 4 题 / 共 7 题 · 排序题

一笔交易从网络传播到节点可查询状态的典型流程如何排列？

  1. 节点按协议验证交易并把有效交易放入候选集合
  2. 提议者把候选交易组织成区块或批次
  3. 交易经点对点网络传播到节点
  4. 各节点执行已接受记录并更新本地账本与状态数据库
  5. 节点通过共识接受一段确定的历史

正确答案：交易经点对点网络传播到节点 → 节点按协议验证交易并把有效交易放入候选集合 → 提议者把候选交易组织成区块或批次 → 节点通过共识接受一段确定的历史 → 各节点执行已接受记录并更新本地账本与状态数据库

传播、验证、提议、共识和状态更新承担不同责任；收到交易不等于它已经提交

第 5 题 / 共 7 题 · 匹配题

将工作量证明与 PBFT 类共识的典型特点匹配

正确答案：工作量证明的参与条件 → 开放参与者通过计算竞争提议区块；工作量证明的确认特点 → 依靠后续区块增加历史被推翻的成本，通常是概率性最终性；PBFT 类的参与条件 → 已知或受控成员交换多轮消息表决；PBFT 类的确认特点 → 在故障假设和法定人数成立时形成确定性提交

两类机制的身份、故障模型、通信成本和最终性不同，不能只按速度比较

第 6 题 / 共 7 题 · 多选题

评估一个跨组织业务是否适合采用区块链时，需要明确哪些边界？

正确答案：参与者之间的信任和共同治理规则、线下事实怎样可靠进入系统、吞吐、确认延迟和协议协调成本、数据删除、更正和隐私要求、复杂查询由账本还是节点状态数据库承担

区块链能协调共同接受的数字记录，但不能自动建立治理，也不能保证外部输入真实

第 7 题 / 共 7 题 · 回想题

为什么不能用比特币的业务规则和性能直接判断所有区块链项目？

对照答案：比特币是把链式记录、点对点网络、工作量证明、激励和数字货币规则组合起来的具体业务系统；区块链是更宽泛的技术组合。许可链可能采用已知身份、PBFT 类共识和不同状态模型，因此评估时必须回到参与者、信任、治理、负载、数据生命周期和查询需求
