READBUF 请求一个未缓存页面时，按处理顺序排列

  1. 检查缓冲区中是否已有目标页面
  2. 若候选页已修改，先按恢复约束写回
  3. 更新缓冲区控制信息并返回页面
  4. 寻找空闲页框或选择可淘汰候选页
  5. 调用操作系统 READ 把目标页面装入页框

正确答案：检查缓冲区中是否已有目标页面 → 寻找空闲页框或选择可淘汰候选页 → 若候选页已修改，先按恢复约束写回 → 调用操作系统 READ 把目标页面装入页框 → 更新缓冲区控制信息并返回页面

缓冲区在内存页框与外存页面之间建立可管理的装入、淘汰和写回路径

第 3 题 / 共 7 题 · 匹配题

将页面状态与淘汰处理匹配

正确答案：被固定或不可释放的页面 → 暂时不能作为淘汰候选；可释放且未修改的页面 → 可直接复用页框；可释放但已修改的页面 → 需满足 WAL 等恢复约束后写回再复用

淘汰资格和脏页状态共同决定是否能够立即释放页框

第 4 题 / 共 7 题 · 匹配题

将页面替换策略与选择依据匹配

正确答案：FIFO → 优先淘汰最早进入缓冲区的可释放页面；LRU → 优先淘汰最长时间未被访问的可释放页面

LRU 利用近期访问局部性，FIFO 只看进入顺序；实际 DBMS 还会使用更复杂近似策略

关于延迟写回，下列哪些说法正确？

正确答案：多次修改可在内存合并，减少重复磁盘写、脏页写回必须受日志与恢复规则约束、故障前未写回的已提交修改需要日志支持 REDO

延迟写回改善 I/O，但必须与 WAL、检查点和提交持久性共同设计

第 7 题 / 共 7 题 · 回想题

用户创建一个新索引后，同一条 SQL 为什么可能更快，而应用代码和逻辑表都不变？

对照答案：CREATE INDEX 建立新的物理存取路径并把定义写入数据字典；优化器可根据统计和代价选择该路径，数据存储层负责维护索引与表的一致。索引属于物理组织，逻辑关系和 SQL 目标不变，因此上层应用可保持稳定，但插入、删除和键修改会增加维护成本
