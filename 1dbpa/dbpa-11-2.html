转储的运行状态与复制范围

教材中的海量转储即全量转储；静态转储先等待事务结束

运行状态海量：复制全部增量：只复制变化
静态：暂停事务形成一致的全库副本复制自上次转储后的变化
动态：事务继续全库副本配合相关日志基础副本、增量与日志配套
Takeaway

静态／动态描述运行状态；海量／增量描述复制范围，两者可以组合

逐次增量：F0 → I1 → I2

独立页样本：I1、I2 都只保存自上一次转储后的变化

文件保存的数据页恢复后 P1 / P2 / P3
周日 F0：全量P1=a，P2=b，P3=ca / b / c
周一 I1：增量只有 P1=a1a1 / b / c
周二 I2：增量只有 P2=b2a1 / b2 / c
误跳过 I1F0 后直接应用 I2a / b2 / c，遗漏 a1
Takeaway

逐次增量依赖前次转储；完整恢复需要 F0、I1 和 I2

先写日志 WAL 的持久化顺序

WAL 约束日志与数据的可靠写入、提交确认；内存页可先修改

场景必须先完成之后才允许
写回脏数据页相应更新日志可靠保存数据页落盘
向客户端确认提交必要更新与提交记录可靠保存返回提交成功

提交前写回数据页

更新日志稳定 → 数据页写回 → 提交记录稳定 → 成功响应

提交后写回数据页

更新与提交日志稳定 → 成功响应 → 数据页稍后写回

Takeaway

数据页可在提交前后写回；可靠更新日志提供撤销依据
