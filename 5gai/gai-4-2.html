### 为什么 Workflow 之后还需要 Skill - Workflow 组织完整流程 - 但流程中的很多局部步骤会反复出现 - 如果每次都重新描述, 成本仍然很高 - Skill 负责把局部稳定经验沉淀下来
![Workflow 与 Skill 关系图](img/c04/workflow-to-skill.svg) #### Workflow 与 Skill 的关系
### 在宣传图片 Workflow 中, 哪些步骤值得沉淀 - 活动信息整理 - 视觉要求规范化 - 输出文件命名与归档 - 定稿前的检查清单
### 不是所有步骤都适合做成 Skill - 目标本身模糊时, 不适合先固化 - 审美判断差异很大时, 不适合硬写死 - 任务变化太大时, 需要重新设计 - Skill 适合稳定重复步骤, 不适合所有问题
### Prompt 与 Skill 的区别 - Prompt: 临时指令, 解决单次任务 - Skill: 稳定方法, 解决一类任务 - Prompt 更灵活 - Skill 更可复用
### 什么样的经验值得沉淀为 Skill - 同类任务重复出现三次以上 - 输入和输出相对稳定 - 步骤相对固定 - 常见错误可以提前预防
### 案例: 从 Workflow 中抽出一个 Skill - 任务: 为校园活动生成宣传图片 - 难点: 活动信息和视觉要求常常写得不规范 - 后果: 每次生成出的图片风格不稳定 - 所以值得先沉淀一个出图前整理 Skill
![从 Workflow 中抽取 Skill](img/c04/skill-extraction.svg) #### 从 Workflow 中抽取 Skill
### 示例 Skill: 宣传图片 Brief 规范化 - 目标: 把零散活动信息整理成稳定出图 Brief - 输入: 主题, 时间地点, 文案要点, 参考风格 - 输出: 可直接用于生成图片的结构化 Brief - 这个 Skill 位于生成之前, 负责稳定输入质量
![Brief Skill 输入输出图](img/c04/brief-io.svg) #### 宣传图片 Brief Skill 的输入与输出
### 这个 Skill 的输入与输出 - 输入应包含活动信息和使用场景 - 输出应包含标题, 副标题, 风格, 色调, 尺寸和禁止事项 - 输出格式应稳定, 方便后续流程复用 - 这样后面的图片生成和审阅才更容易稳定
### Skill 不只是更长的 Prompt - 它不是一句话写得更复杂 - 它强调任务边界和执行顺序 - 它强调输入, 输出和检查标准 - 它更像一个小型方法包
### Skill 的基本组成 - `SKILL.md`: 任务目标, 边界, 步骤, 输出要求 - `scripts/`: 把固定动作变成可执行步骤 - `references/`: 提供术语, 模板, 规范和知识依据 - 三者组合后, Skill 才更像稳定能力
![Skill 组成结构图](img/c04/skill-package.svg) #### Skill 组成: 文档, 脚本与参考材料
### `SKILL.md` 的作用 - 说明这类任务要解决什么问题 - 说明什么时候适合用, 什么时候不适合 - 说明推荐步骤和输出格式 - 说明常见错误和注意事项
### `scripts/` 的作用 - 把重复动作固化为可执行命令 - 减少每次手工点击和复制粘贴 - 提高执行的一致性 - 让 AI 和人都更容易复用
### `references/` 的作用 - 提供稳定知识源 - 避免每次都重新解释术语 - 保证输出遵循相同标准 - 减少模型凭印象乱猜
### 什么不适合沉淀为 Skill - 任务目标每次都完全不同 - 结果主要依赖临场创意判断 - 团队内部还没有稳定做法 - 没有明确输入和输出边界
### Skill 与 Workflow 的关系 - Workflow 负责组织多步骤流程 - Skill 负责稳定完成局部环节 - 一个 Workflow 里可以包含多个 Skill - Workflow 越清晰, Skill 越容易复用
### 课堂练习二: 从 Workflow 中识别 Skill - 继续使用宣传图片案例 - 找出其中最值得沉淀的一个步骤 - 写出输入, 输出和检查项 - 说明哪些部分应放进 `scripts/` 或 `references/`
### 本节结论 - Skill 是把一次成功变成稳定能力 - Skill 不只是 `SKILL.md` - 它通常由说明, 脚本和参考材料组成 - 会设计 Skill, 才算真正开始积累 AI 协作资产
