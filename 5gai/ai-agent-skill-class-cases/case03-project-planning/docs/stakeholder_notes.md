# 相关人员意见记录

以下是几位“相关人员”的意见。它们不完全一致，需要整理和取舍。

## 教师 A 的意见

我希望这个工具能帮助学生形成 AI 使用反思，不要只是记录“我用了什么工具”。

最好每个任务都能填写：

- 使用的提示词数量；
- 最终是否满意；
- 哪些内容是 AI 生成的；
- 哪些内容是自己修改的。

## 教师 B 的意见

不要做得太复杂。学生编程基础弱，如果功能太多，他们只会复制粘贴。

我希望最后的项目结构足够清楚，最好只有：

- `index.html`
- `style.css`
- `app.js`

不要引入框架，不要使用 React，不要使用构建工具。

## 学生代表的意见

最好能看起来好看一点，不要像表格作业。

希望有颜色区分不同状态，比如：

- 未开始
- 进行中
- 已完成
- 需要修改

另外，希望刷新页面后任务不要消失。

## 助教的意见

希望最后能导出数据，至少能把任务列表导出成 JSON 文件。

但导入功能可以先不做。

## 课程设计者的意见

这个案例主要用于讲 AI 辅助编程，不是为了做一个真正上线的系统。

所以关键不是功能多，而是流程清楚：

1. 先整理需求；
2. 再拆任务；
3. 再写代码；
4. 最后按验收标准检查。
