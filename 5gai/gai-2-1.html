### 提示词工程 (Prompt Engineering) 背景 - 大语言模型能生成文本代码解释和推理 - 模型能力很强但输出质量依赖提问方式 - 同一问题不同提示词会得到完全不同的结果 - Prompt Engineering 因此成为人与 AI 交互的重要方法 - 本章重点是理解如何设计清晰有效的提示词
### 提示词工程的发展阶段 - 2023 年 Prompt Engineering 被认为是核心技术 - 大量指南和模板被提出用于优化提问方式 - 2024 年开始出现 Tool use RAG 和 AI Agent - 2025 年越来越多研究提出 Context Engineering - Prompt 不再是全部 - 但仍然是 AI 系统的重要基础
### 提示词的基本作用 - 指定 AI 要完成的任务 - 提供必要的背景信息 - 指定输出结构或写作风格 - 引导模型进行推理或分析 - 降低模型生成错误或偏差的概率
### 提示词的本质 - Prompt 不是简单的命令 - Prompt 是对问题的结构化表达 - Prompt 反映提问者对问题的理解程度 - 高质量 Prompt 往往来自深度思考 - AI 输出质量近似等于问题定义质量
### 与大语言模型 对话 的基本原则 - 明确任务: 不要提出模糊问题 - 提供背景: 让模型理解情境 - 指定角色: 帮助模型选择合适语气 - 指定结构: 控制输出组织方式 - 允许迭代: 通过多轮对话改进结果
### 原则一 明确任务 - 模糊问题往往产生模糊答案 - 清晰任务可以减少不相关内容 - 指定主题范围和目标 - 可以同时指定字数或内容深度 - 明确任务是提示词设计的第一步
### 原则二 提供背景 - LLM 不了解用户当前情境 - 提供背景可以减少误解 - 背景可以包括专业学习阶段或使用目的 - 背景越清晰模型越容易生成合适内容 - Context 是 Prompt 的重要组成部分
### 原则三 指定角色 - 指定角色可以影响输出风格 - 角色设定可以帮助模型选择适当语气 - 角色提示可以提高内容一致性 - Role Prompting 是最常见的技巧之一
### 原则四 指定输出结构 - 输出结构可以控制内容组织 - 可以指定标题列表或分段方式 - 可以要求使用 Markdown 或表格 - 明确结构可以减少冗余内容 - Structured Output 提高可读性
### 原则五 提供示例 - 示例可以帮助模型理解 任务模式 - Few shot Prompting 是常见方法 - 示例可以展示输入和输出对应关系 - 模型通过示例学习任务结构 - 示例数量不必太多 - 关键是清晰
### 原则六 逐步推理 - 复杂问题需要逐步分析 - Chain of Thought 可以引导推理 - 模型先解释思路再给出答案 - 逐步推理可以减少逻辑错误 - 这种方法在数学或分析任务中常见
### 常见提示词框架 的作用 - 框架提供组织 Prompt 的结构 - 框架帮助用户思考任务要素 - 框架减少 Prompt 设计的随意性 - 框架有助于学习标准化表达 - 但框架只是工具关键仍是理解问题
### RTF 框架 - RTF 代表 Role Task Format - Role 指定 AI 的角色 - Task 指定需要完成的任务 - Format 指定输出形式 - 结构简单适合初学者
### CO-STAR 框架 - Context 描述任务背景 - Objective 描述任务目标 - Style 指定写作风格 - Tone 指定语气 - Audience 指定读者群体 - Response 指定输出形式
### Few-Shot Prompting - Few Shot 指提供少量示例 - 示例展示输入与输出的关系 - 模型通过示例模仿任务结构 - 常用于分类或格式化任务 - 示例质量比示例数量更重要
### Chain of Thought Prompting - 引导模型逐步进行推理 - 常用于逻辑分析或数学问题 - 可以减少推理过程中的错误 - 通过提示先分析再回答 - 提高复杂任务的正确率
### 提示词工程的常见误区 - 将 AI 当作搜索引擎使用 - 认为一次提问就能得到完美答案 - 认为 Prompt 越长越好 - 忽略任务拆解 - 忽略对输出结果的评估
### 误区一 将 AI 当作搜索引擎 - 搜索引擎返回已有网页 - LLM 根据概率生成文本 - 两者机制完全不同 - 使用方式也应不同 - Prompt 应描述任务而不是关键词
### 误区二 期待一次完美答案 - AI 输出是概率生成结果 - 结果可能需要多次修改 - Prompt 设计通常需要迭代 - 用户需要不断调整问题 - 人机协作是重要过程
### 误区三 Prompt 越长越好 - 长 Prompt 不一定更清晰 - 关键在于信息结构 - 冗余信息可能造成干扰 - 好 Prompt 通常结构清晰 - 简洁但完整的 Prompt 更有效
### 误区四 忽略任务拆解 - 复杂任务不应一次完成 - 可以拆分为多个步骤 - 例如收集信息、分析、再写作 - 逐步任务更容易获得好结果 - Task Decomposition 是重要策略
### 提示词工程与批判性思维 - Prompt 设计 需要理解问题 - 需要判断哪些信息重要 - 需要组织逻辑结构 - 需要评估 AI 输出质量 - 因此 Prompt Engineering 与思维能力密切相关
### 人机协作的基本循环 - 用户提出问题 - AI 生成初步回答 - 用户评估结果 - 用户修改 Prompt - 人机协作 不断改进答案
### 案例一 研究报告任务 - 初始 Prompt 可能过于简单 - 例如写一篇关于 AI 的文章 - 输出通常较为泛泛 - 可以逐步增加任务约束 - 最终得到结构清晰的报告
### 改进 Prompt 的方法 - 明确研究主题 - 指定文章结构 - 指定读者群体 - 指定字数范围 - 指定是否需要引用
### 案例二 学习一门课程 - 初始问题往往非常笼统 - 例如我想学习机器学习 - 模型难以判断学习目标 - 可以增加背景信息 - 例如专业基础、学习时间和目标
### 学习路径 Prompt 的改进 - 指定学习目标 - 指定学习周期 - 指定学习资源类型 - 要求输出学习计划 - 要求分阶段安排
### 案例三 翻译与理解 - 简单 Prompt 只是翻译文本 - 改进 Prompt 可以加入解释 - 可以要求解释专业术语 - 可以要求提供背景知识 - 可以帮助读者更好理解内容
### 提示词工程的未来角色 - Prompt 不再是唯一接口 - AI 系统逐渐加入工具和记忆 - Context Engineering 越来越重要 - Agent 系统 会自动调用多个模型 - 但 Prompt 仍然是基础能力
### 结论 - Prompt Engineering 是人与 AI 的沟通方式 - 高质量 Prompt 来自清晰问题定义 - Prompt 框架可以帮助组织思路 - Prompt 设计需要不断迭代 - 最终目标是提升问题理解能力
