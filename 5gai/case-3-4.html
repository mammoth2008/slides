3.4 案例 4: 制作 Trae Skill

### 本节目标 - **认识 Skill**: 它不是代码, 而是可复用工作流程 - **理解结构**: 名称, 描述, 触发场景, 步骤, 输出 - **完成案例**: 自己写一个 `SKILL.md` - **观察效果**: 同一任务, 有无 Skill 的输出差异 - **形成判断**: 什么任务值得固化成 Skill
### Trae Skill 是什么 - **定位**: 给 Agent 的专业能力说明书 - **作用**: 告诉 AI 在某类任务中应该怎样做 - **不是**: 不是插件, 不是脚本, 不是自动万能工具 - **适合**: 重复流程, 规范要求, 多步骤组合任务 - **不适合**: 一次性问题, 没有规则的创意闲聊
### 可确认的基本规则 - **使用场景**: 主要在 Trae SOLO 中使用 - **创建入口**: 设置 → 规则和技能 → 技能 - **导入方式**: 可上传 `Skill.md`, 由 Trae 解析 - **项目位置**: 社区常用 `.trae/skills/` - **调用方式**: 建议明确说 "使用 XX 技能"
### Rules, Skills, MCP - **Rules**: 项目底线, 入口索引, 始终生效 - **Skills**: 场景知识, 操作流程, 按需触发 - **MCP**: 外部工具, 让 AI 能打开浏览器或读写服务 - **比喻**: Rules 是规矩, Skills 是做法, MCP 是工具 - **原则**: Rules 精简, Skills 具体, MCP 够用
### 最小 SKILL.md 模板 - name: data-cleaning-report - description: 清洗数据并生成报告时使用。 - 目标 - 工作流程
### 一个好 Skill 至少写清 - **何时使用**: 触发场景和关键词 - **读取什么**: 输入目录, 输入文件, 先后顺序 - **怎样处理**: 关键步骤和禁止动作 - **输出什么**: 文件名, 格式, 存放位置 - **如何验收**: 自查清单和失败处理
### 课堂制作步骤 - **第 1 步**: 选择一个重复任务 - **第 2 步**: 写出人会怎样做 - **第 3 步**: 转成 `SKILL.md` - **第 4 步**: 用同一材料跑两次, 对比有无 Skill - **第 5 步**: 根据错误修改 Skill
### 案例一: 数据处理 - **任务**: 清洗 CSV 或 Excel, 生成小报告 - **材料**: 学生成绩, 问卷, 销售, 学习行为数据 - **输出**: `cleaned.csv`, `summary.md`, `issues.md` - **Skill 价值**: 不让 AI 静默删除异常值 - **课堂重点**: 数据处理必须可追溯
### 数据处理 Skill 规则 - **先读数据字典**: 不直接猜字段含义 - **原始文件只读**: 清洗结果另存到 `output/` - **异常先记录**: 无法判断的值写入 `issues.md` - **统计要可复算**: 写清口径, 不只给结论 - **报告要短**: 说明处理规则和主要发现
### 案例二: 课程笔记/录音 - **任务**: 把转写稿整理成学习材料 - **材料**: 课堂录音转写, 零散笔记, PPT 文本 - **输出**: 摘要, 概念表, 复习题, 待核对点 - **Skill 价值**: 区分原文事实与 AI 推断 - **课堂重点**: 不清楚的内容不能补成事实
### 笔记处理 Skill 规则 - **保留来源**: 每个概念尽量回到原始片段 - **标出不确定**: 听不清, 缺上下文, 疑似错词 - **分层输出**: 摘要, 概念, 例子, 问题 - **面向复习**: 生成小测题和待复习清单 - **禁止编造**: 不补没有讲过的案例
### 案例三: 写一个游戏 - **任务**: 生成一个可运行的 HTML 小游戏 - **选题**: SQL 闯关, 数据库索引消消乐, 躲避游戏 - **输出**: `index.html`, `style.css`, `game.js` - **Skill 价值**: 先设计规则, 再写代码 - **课堂重点**: 游戏必须可玩, 不只是好看的页面
### 游戏 Skill 规则 - **先写规格**: 玩法, 操作, 胜负条件 - **再写代码**: HTML, CSS, JS 分文件 - **状态完整**: 开始, 运行, 胜利, 失败, 重开 - **交互明确**: 键盘或鼠标操作要可见 - **自查运行**: 本地打开不能空白或报错
### 案例四: SQLite 管理系统 - **任务**: 做一个简单 MIS 原型 - **场景**: 图书借阅, 课程签到, 实验设备, 社团成员 - **路线**: Python + Flask 或 Streamlit + SQLite - **输出**: 数据库, 增删改查, README, 测试数据 - **课堂重点**: 需求 → 数据模型 → 功能 → 验证
### SQLite Skill 规则 - **先画表**: 实体, 字段, 主键, 关系 - **再建库**: `schema.sql`, `seed.py`, `app.db` - **参数化 SQL**: 不拼接用户输入 - **功能闭环**: 新增, 查询, 修改, 删除 - **说明清楚**: README 写启动和测试方法
### 四个案例怎么安排 - **入门**: 课程笔记 Skill, 最容易看出流程价值 - **数据**: 数据处理 Skill, 最容易训练严谨性 - **编程**: 游戏 Skill, 最容易激发兴趣 - **系统**: SQLite MIS Skill, 最接近信息管理专业 - **比较**: 每组必须展示修改前后的 Skill
### 评价 - 触发清晰 - 流程完整 - 边界明确 - 输出稳定 - 可迁移
### 提醒 - **不要迷信自动触发**: 手动指定 Skill - **不要写太长**: 初学 Skill 控制在 5 个步骤左右 - **不要只看结果**: 要看 AI 是否按流程做事 - **不要隐藏错误**: 错误正是修改 Skill 的材料 - **最后追问**: 重复操作才值得写 Skill
