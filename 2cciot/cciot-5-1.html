### 容器云 - 将应用程序及其依赖打包成独立运行环境 - 共享主机操作系统内核
![Container VS Virtual Machine](img/c05/1-container_vs_vm.png) #### Container VS Virtual Machine
### 容器技术 - 一种封装技术 - 存储程序及其依赖 - 每个容器都可以单独运行 - 操作系统虚拟化
![Container Technology](img/c05/2-container-technology.jpg) #### Container Technology
### 优势 - 启动速度快 - 资源使用率高 - 运行环境一致性好 - 易于构建和部署 - 可移植性强
### 主流容器技术 - Google Borg - Docker - Kubernetes - containerd
### Google Borg - 2000 年代初开发 - 调度和管理大规模分布式计算任务 - 资源利用率高 - 支撑搜索、Gmail、YouTube 等服务 - 谷歌内部使用, 未对外开放 - 为 Kubernetes 提供核心理念和经验
![Google Borg](img/c05/3-borg.jpg) #### Google Borg
### Docker - 2013 年发布 - 推动容器技术走向主流 - 通过容器打包和运行应用 - 轻量、跨平台、容易分发和部署 - 生态活跃 - 在大规模集群管理方面能力有限 - 推动了微服务架构和 DevOps 流程普及
![Docker](img/c05/4-docker-container.png) #### Docker
![Docker](img/c05/5-docker-container.png) #### Docker
### containerd - 由 Docker 拆分而来 - 2017 年捐赠给 CNCF (云原生计算基金会) - 是轻量级容器运行时, 管理容器生命周期 - 简洁、稳定 - Kubernetes 默认支持的容器运行时之一 - 不提供镜像构建、网络和存储等功能 - 更底层, 与 Kubernetes、Docker 等平台结合使用
![containerd](img/c05/7-containerd.png) #### containerd
### Kubernetes - 2014 年由谷歌开源 - 借鉴 Borg 和 Omega 的经验 - 社区活跃、生态庞大 - 支持自动伸缩、滚动升级、高可用 - 学习曲线陡峭, 集群管理复杂 - 事实上的容器编排标准 - 广泛用于云原生架构 - 用于调度和运行容器 - 容器自动部署、扩展和管理
![Kubernetes](img/c05/6-k8s.jpeg) #### Kubernetes
### Kubernetes 结构 - 主控节点 Master - 工作节点 Node - 容器组 Pod
![Kubernetes Cluster Architecture](img/c05/8-kubernetes-cluster-architecture.svg) #### Kubernetes Cluster Architecture
![Kubernetes System](img/c05/10-k8s.png) #### Kubernetes System
### 主控节点 Master - 负责全局调度与管理 - 维护集群状态 - 决定容器部署位置 - 提供 API 接口 - 保证集群一致性与调度智能化 - 对高可用要求高, 单点故障会影响集群控制 - 生产环境通常部署多个 Master 节点实现高可用
![Kubernetes Master](img/c05/9-k8s-system.png) #### Kubernetes Master
### 工作节点 Node - 运行容器化应用的计算资源单元 - 可以是物理机或虚拟机 - 负责运行 Pod, 提供计算、存储、网络资源 - 可水平扩展, 支持自动伸缩, 负载分布灵活 - 单个节点可能受资源瓶颈限制 - 节点状态由 Master 统一监控和调度
![Kubernetes Node](img/c05/11-k8s-nodes.png) #### Kubernetes Node
### 容器组 Pod - Kubernetes 中最小的调度单元 - 一个或多个容器的集合 - 共享网络、存储等资源, 运行在同一 Node 上 - 支持多容器协作, 简化服务部署和通信 - 生命周期短暂 - 通常运行一个主容器 - 辅以日志、监控等 sidecar 容器
